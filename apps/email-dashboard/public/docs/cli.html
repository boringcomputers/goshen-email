Integrations

CLI

A JSON command-line client for scripts and shells. Every API operation, dry runs, and schema output.

Availability

The CLI is bezalel-email, built from the Goshen Email repository and not yet published to npm. From a checkout after pnpm build, run it as node packages/email-cli/dist/main.js. Node.js 24 is required. The examples below assume the binary is on your PATH.

Configuration

export BEZALEL_API_KEY="bze_..."
export BEZALEL_BASE_URL="https://bezalel-email-standalone.michaelwasihun96.workers.dev"   # optional; defaults to the hosted API

The key is read from the environment only. There is no flag for it and no config file, so it cannot end up in shell history.

Passing input

Simple fields are flags in kebab case; array fields repeat the flag:

bezalel-email inboxes create --username research --group agents
bezalel-email messages list --inbox-id research@agents.goshenemail.com --labels received --labels unread --limit 20
bezalel-email messages send --inbox-id research@agents.goshenemail.com \
  --to vendor@example.net --subject "Quote request" --text "Could you send the current quote?" \
  --idempotency-key 2f7c1c1e-6d1a-4a3b-9b0e-0c9b3f5c8a11

Anything more complex goes in --json, either inline or from stdin with -:

bezalel-email inboxes update --json '{"inboxId":"research@agents.goshenemail.com","group":null}'
bezalel-email messages send --json - < approved-message.json

send and reply require --idempotency-key (or idempotencyKey in the JSON). See Sending mail for why.

Output

Results are JSON on stdout, one document per command, so they pipe into jq:

bezalel-email threads list --inbox-id research@agents.goshenemail.com --labels unread | jq -r '.threads[].subject'

Errors are JSON on stderr with code, message, and transient, and the exit status is 1.

Dry runs and schemas

--dry-run validates the input against the published schema and prints the request that would be sent, with the authorization header redacted. Nothing contacts the API.

bezalel-email messages send --dry-run --inbox-id research@agents.goshenemail.com --to a@example.net --text hi --idempotency-key k1

--schema after a command prints that operation's JSON Schema; bezalel-email --schema prints all of them. Useful for generating forms or validating input in another language.

The dry run checks the published schema. The server also enforces limits JSON Schema cannot express (combined body and attachment sizes, recipient totals), so a request that passes a dry run can still be rejected.
