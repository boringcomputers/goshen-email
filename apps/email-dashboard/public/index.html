01

Create an inbox

One call creates an address with its own message store. Group inboxes by project, and hand each agent a key that reaches only its own mail.

03

Step in when it matters

Mail that fails sender checks, or scans as spam or malware, waits in quarantine. Only a person can release it, from the dashboard.

However your agent is built, it can use email.

Agents reach the same inboxes through the REST API, the JSON CLI, or the MCP server. People see the same mail in the dashboard. One account key works everywhere.

Connect with
.mcp.json shell curl 
{
  "mcpServers": {
    "goshenemail": {
      "url": "https://api.goshenemail.com/mcp",
      "headers": {
        "Authorization": "Bearer ${GOSHENEMAIL_API_KEY}"
      }
    }
  }
}

// Tools the key's scopes allow:
// list_inboxes   create_inbox   list_messages
// search_messages   get_thread   send   reply
$ export GOSHENEMAIL_API_KEY="bze_..."

$ goshenemail inboxes create --username procurement

$ goshenemail threads list \
    --inbox-id procurement@agents.goshenemail.com \
    --labels unread

$ goshenemail messages reply --json - < reply.json

# Every command prints JSON, so it pipes into jq.
curl https://api.goshenemail.com/v1/inboxes \
  -H "Authorization: Bearer $GOSHENEMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"username":"procurement"}'

# The OpenAPI document:
# https://api.goshenemail.com/openapi.json
  • REST API17 operations, all described in one OpenAPI document. Call it from any language.
  • MCP serverHosted over HTTP or local over stdio, for Claude Code, Cursor, Codex, or any MCP client.
  • CLIEvery operation from scripts and shells, with JSON output you can pipe.
  • TriageA category, whether a reply is needed, and how urgent it is, on each new message.
  • Safe retriesEvery send carries an idempotency key. Retry a timed-out send with the same key and contents, and it never goes out twice.

  • An account key reaches its account's inboxes with only the scopes you pick. A mailbox key reaches a single inbox.
  • No key can release quarantine or create other keys. Those stay with the people who sign in.
  • Account keys are shown once, stay masked in the dashboard, and can be revoked at any time.
  • The dashboard calls the API from its server. Its service credentials never reach your browser.
  • You sign in with a link or code sent to your email. There is no password to leak.
